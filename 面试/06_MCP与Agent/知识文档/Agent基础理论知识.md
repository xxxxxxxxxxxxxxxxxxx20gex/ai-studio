## 一、Agent基本概念 ⭐⭐⭐

### 1. 什么是Agent？

**定义:**
- Agent（智能体）= LLM + 推理能力 + 工具调用 + 记忆
- 能够感知环境、自主决策、执行动作的AI系统

**核心能力:**
- 🧠 推理：分析问题，制定计划
- 🔧 工具使用：调用外部工具完成任务
- 💾 记忆：记住上下文和历史
- 🔄 反思：评估结果，优化策略

### 2. Agent vs LLM

| 特性 | 传统LLM | Agent |
|------|---------|-------|
| 能力范围 | 文本生成 | 自主决策+执行 |
| 工具使用 | 无 | 可调用外部工具 |
| 任务执行 | 一次性回答 | 多步骤规划执行 |
| 反馈循环 | 无 | 可根据结果调整策略 |
| 典型应用 | 问答、写作 | 任务自动化、问题解决 |

### 3. Agent的核心组件

```
┌─────────────────────────────────┐
│         Agent 架构               │
├─────────────────────────────────┤
│  1. 大语言模型 (LLM Core)       │

│                                 │
│  2. 工具集 (Tools)              │
│     - 搜索引擎                   │

│     - API调用                    │
│     - 代码执行                   │

│  3. 记忆系统 (Memory)           │
│     - 短期记忆（对话历史）       │
│     - 长期记忆（知识库）         │
│                                 │
│  4. 规划器 (Planner)            │
```

## 二、推理框架（必考）⭐⭐⭐⭐⭐

### 1. ReAct (Reasoning + Acting) ⭐⭐⭐⭐⭐

**核心思想:** 推理和行动交替进行

**流程:**
```
Thought (思考) → Action (行动) → Observation (观察) 
    ↓                                    ↑
    └────────────────循环─────────────────┘
```

**示例:**
```
Question: 2023年诺贝尔物理学奖得主是谁？

Thought 1: 我需要搜索2023年诺贝尔物理学奖的信息
Action 1: Search["2023年诺贝尔物理学奖得主"]
Observation 1: Pierre Agostini, Ferenc Krausz, Anne L'Huillier

Thought 2: 我找到了答案，是三位科学家
Action 2: Finish["2023年诺贝尔物理学奖得主是..."]
```

**优势:**
- 可解释性强（能看到推理过程）
- 可纠错（观察结果后可调整）
- 适合复杂任务


### 2. Chain-of-Thought (CoT) ⭐⭐⭐⭐⭐

**核心思想:** 让模型逐步推理，展示思考过程

**类型:**

**Zero-shot CoT:**
```
Prompt: "Let's think step by step..."
→ 模型自动分步推理
```

**Few-shot CoT:**
```
提供带推理过程的示例:

Q: 商店有15个苹果，卖了8个，又进了12个，现在有多少？
A: 让我一步步想：
   1. 初始：15个
   2. 卖了8个：15-8=7个
   3. 又进12个：7+12=19个
   答案：19个

Q: [新问题]
A: 让我一步步想：...
```

**应用场景:**
- 数学问题
- 逻辑推理
- 复杂决策


### 3. Tree-of-Thought (ToT) ⭐⭐⭐

**核心思想:** 探索多个推理分支，选择最优路径

**流程:**
```
          问题
        ↙ ↓ ↘
    思路1 思路2 思路3
    ↙↘   ↙↘   ↙↘
   ... (展开成树)

评估每个分支，选择最优路径
```

**适用场景:**
- 需要探索多种可能性
- 创意任务（写作、设计）
- 游戏AI


### 4. ReWOO (Reasoning WithOut Observation) ⭐⭐⭐

**核心思想:** 先规划好所有步骤，再批量执行

**对比ReAct:**
```
ReAct: 思考→行动→观察→思考→行动... (串行)
ReWOO: 思考→规划所有步骤→批量执行 (并行)
```

**优势:**
- 减少LLM调用次数
- 可并行执行工具
- 更高效


### 5. Plan-and-Execute ⭐⭐⭐⭐

**核心思想:** 先制定完整计划，再逐步执行

**流程:**
```
1. Planner: 将任务分解成步骤
2. Executor: 逐步执行
3. Re-plan: 根据结果动态调整
```

**面试重点**
- ✅ 能说出ReAct和CoT的区别
- ✅ 理解各种框架的适用场景
- ✅ 知道ReAct的Thought-Action-Observation循环

## 三、提示词工程 ⭐⭐⭐⭐⭐

### 1. 什么是提示词工程？

**定义:**
- 提示词工程（Prompt Engineering）是通过精心设计输入文本来引导LLM产生期望输出的技术
- 是Agent与LLM交互的核心接口，直接影响Agent的推理质量和行为表现

**核心价值:**
- 🎯 提升模型理解准确性
- 🧠 激发模型推理能力
- 🔧 控制模型输出格式
- 💡 引导模型思考路径

**提示词在Agent中的作用:**
```
用户意图 → 提示词工程 → LLM理解 → 推理决策 → 工具调用 → 结果整合
              ↑
        核心控制点
```

### 2. 提示词设计原则 ⭐⭐⭐⭐⭐

#### 原则1: 清晰明确（Clarity）
**要求:** 指令要具体、无歧义

**❌ 不好的提示词:**
```
"帮我分析一下数据"
```

**✅ 好的提示词:**
```
"请分析以下销售数据，计算：
1. 总销售额
2. 同比增长率
3. 各产品类别占比
输出格式：JSON"
```

#### 原则2: 提供上下文（Context）
**要求:** 给出足够的背景信息

**示例:**
```
"你是一位资深Python开发工程师，擅长代码审查。
请审查以下代码，指出：
1. 潜在的bug
2. 性能问题
3. 代码风格问题
4. 改进建议

代码：
[代码内容]"
```

#### 原则3: 结构化输出（Structure）
**要求:** 明确指定输出格式

**示例:**
```
"请按以下格式输出分析结果：

## 问题分析
[分析内容]

## 解决方案
1. [方案1]
2. [方案2]

## 风险评估
[风险内容]"
```

#### 原则4: 分步骤引导（Step-by-step）
**要求:** 将复杂任务分解为步骤

**示例:**
```
"请按以下步骤完成任务：
步骤1: 理解问题需求
步骤2: 分析相关数据
步骤3: 提出解决方案
步骤4: 评估方案可行性"
```

### 3. 基础提示词模式 ⭐⭐⭐⭐⭐

#### 3.1 Zero-shot Prompting

**定义:** 不提供示例，直接给出任务指令

**示例:**
```
"将以下中文翻译成英文：
'人工智能正在改变世界'"
```

**适用场景:**
- 简单明确的任务
- 模型已经理解的任务类型

#### 3.2 Few-shot Prompting

**定义:** 提供少量示例，让模型学习模式

**示例:**
```
"将以下中文翻译成英文：

示例1:
中文: '你好'
英文: 'Hello'

示例2:
中文: '谢谢'
英文: 'Thank you'

现在翻译：
中文: '再见'
英文: ?"
```

**优势:**
- 快速适应新任务
- 不需要微调模型
- 可解释性强

**适用场景:**
- 需要特定格式的输出
- 模型不熟悉的任务类型
- 需要展示期望的行为模式

#### 3.3 Role-based Prompting（角色扮演）

**定义:** 给模型指定一个角色，引导其行为

**示例:**
```
"你是一位经验丰富的软件架构师，擅长系统设计。
请为以下需求设计系统架构：
[需求描述]"
```

**常见角色:**
- 专家角色：资深工程师、数据分析师、产品经理
- 助手角色：代码助手、写作助手、学习助手
- 评估角色：代码审查员、质量检查员、安全专家

**优势:**
- 激活模型相关知识
- 引导模型采用特定视角
- 提升输出专业性

#### 3.4 Chain-of-Thought (CoT) Prompting

**定义:** 引导模型展示推理过程（已在推理框架章节详述）

**与推理框架的关系:**
- CoT是提示词工程的一种模式
- 通过提示词设计实现逐步推理
- 是Agent推理能力的基础

**Zero-shot CoT:**
```
"问题: 一个数的3倍加5等于17，这个数是多少？
让我们一步步思考："
```

**Few-shot CoT:**
```
"问题: 商店有15个苹果，卖了8个，又进了12个，现在有多少？
解答: 
步骤1: 初始有15个
步骤2: 卖了8个，剩余 15-8=7个
步骤3: 又进12个，现在有 7+12=19个
答案: 19个

问题: [新问题]
解答: 让我们一步步思考："
```

### 4. 高级提示词技巧 ⭐⭐⭐⭐

#### 4.1 Self-Consistency（自我一致性）

**核心思想:** 生成多个推理路径，选择最一致的答案

**实现方式:**
```
1. 用同一个问题生成多个CoT推理过程
2. 收集所有答案
3. 选择出现频率最高的答案（或最一致的答案）
```

**示例:**
```
问题: "计算 23 + 45"

生成3次推理：
推理1: 23 + 45 = 68
推理2: 23 + 45 = 68  
推理3: 23 + 45 = 68

最终答案: 68（一致性高）
```

**优势:**
- 提高答案准确性
- 减少随机错误
- 适合复杂推理任务

#### 4.2 Few-shot Chain-of-Thought

**核心思想:** 结合Few-shot和CoT，提供带推理过程的示例

**示例:**
```
"解决以下数学问题，展示你的思考过程：

问题1: 小明有10元，买了3元的笔，还剩多少？
解答: 
  初始: 10元
  花费: 3元
  剩余: 10 - 3 = 7元
答案: 7元

问题2: 一本书原价50元，打8折后多少钱？
解答: 
  原价: 50元
  折扣: 8折 = 0.8
  折后价: 50 × 0.8 = 40元
答案: 40元

问题3: [新问题]
解答: [模型生成推理过程]"
```

#### 4.3 Prompt Chaining（提示词链）

**核心思想:** 将复杂任务分解为多个提示词步骤

**流程:**
```
步骤1提示词 → 结果1
    ↓
步骤2提示词（包含结果1） → 结果2
    ↓
步骤3提示词（包含结果2） → 最终结果
```

**示例:**
```
# 步骤1: 需求分析
"分析以下用户需求，提取关键信息：
[用户需求]"

# 步骤2: 方案设计（基于步骤1结果）
"基于以下需求分析，设计解决方案：
[需求分析结果]"

# 步骤3: 方案评估（基于步骤2结果）
"评估以下方案的可行性：
[设计方案]"
```

**在Agent中的应用:**
- 任务规划阶段：分解任务为子步骤
- 工具调用阶段：为每个工具调用设计提示词
- 结果整合阶段：设计结果汇总提示词

#### 4.4 Template-based Prompting（模板化提示词）

**核心思想:** 设计可复用的提示词模板

**模板示例:**
```
"你是一位{role}，擅长{expertise}。

任务: {task}
输入: {input}
约束: {constraints}

请按以下格式输出：
{output_format}"
```

**使用示例:**
```
role = "资深Python工程师"
expertise = "代码审查和优化"
task = "审查以下代码"
input = "[代码内容]"
constraints = "关注性能、安全、可读性"
output_format = "JSON格式，包含问题列表和改进建议"
```

**优势:**
- 提高开发效率
- 保持一致性
- 易于维护和优化

### 5. 提示词在Agent中的应用 ⭐⭐⭐⭐⭐

#### 5.1 Agent系统提示词（System Prompt）

**作用:** 定义Agent的身份、能力和行为准则

**示例:**
```
"你是一个智能助手Agent，具有以下能力：
1. 理解用户意图
2. 调用工具完成任务
3. 推理和决策
4. 记忆和总结

行为准则：
- 始终以用户需求为中心
- 在不确定时主动询问
- 解释你的推理过程
- 承认错误并纠正"
```

#### 5.2 工具调用提示词

**作用:** 引导Agent正确选择和使用工具

**示例:**
```
"可用工具：
1. search(query): 搜索信息
2. calculator(expression): 计算数学表达式
3. get_weather(city): 获取天气信息

用户需求: {user_input}

请分析需求，决定：
1. 是否需要调用工具？
2. 调用哪个工具？
3. 工具参数是什么？

格式：
Thought: [你的思考]
Action: [工具名称]
Action Input: [工具参数]"
```

#### 5.3 ReAct提示词模板

**作用:** 实现ReAct推理框架的提示词设计

**模板:**
```
"你可以使用以下工具：
{tools_description}

使用以下格式：
Question: [输入问题]
Thought: [你需要思考做什么]
Action: [要执行的动作，格式: tool_name(arguments)]
Observation: [动作的结果]
... (可以重复 Thought/Action/Observation)
Thought: [我现在知道最终答案了]
Final Answer: [最终答案]"
```

#### 5.4 记忆检索提示词

**作用:** 引导Agent从记忆中检索相关信息

**示例:**
```
"根据以下对话历史，回答用户问题：

对话历史:
{conversation_history}

当前问题: {current_question}

请：
1. 从对话历史中检索相关信息
2. 如果信息不足，说明需要什么额外信息
3. 基于检索到的信息回答问题"
```

### 6. 提示词优化策略 ⭐⭐⭐⭐

#### 6.1 迭代优化流程

```
初始提示词
    ↓
测试效果
    ↓
发现问题
    ↓
修改提示词
    ↓
再次测试
    ↓
达到目标效果
```

#### 6.2 常见优化技巧

**1. 添加约束条件**
```
❌ "写一篇文章"
✅ "写一篇800字的技术文章，主题是AI，要求逻辑清晰、有实例"
```

**2. 明确输出格式**
```
❌ "分析数据"
✅ "分析数据，输出JSON格式：
{
  'summary': '...',
  'insights': [...],
  'recommendations': [...]
}"
```

**3. 提供负面示例**
```
"请写代码，注意：
❌ 不要使用全局变量
❌ 不要硬编码配置
✅ 使用函数封装
✅ 添加错误处理"
```

**4. 使用思维链引导**
```
"解决这个问题，让我们一步步思考：
1. 首先理解问题
2. 然后分析关键因素
3. 最后提出解决方案"
```

#### 6.3 提示词评估指标

- **准确性:** 输出是否符合预期
- **相关性:** 输出是否与任务相关
- **完整性:** 是否包含所有必要信息
- **格式正确性:** 是否符合指定格式
- **一致性:** 多次运行结果是否稳定

### 7. 提示词工程最佳实践 ⭐⭐⭐⭐

#### 7.1 设计流程

```
1. 明确任务目标
   ↓
2. 分析模型能力
   ↓
3. 设计初始提示词
   ↓
4. 测试和评估
   ↓
5. 迭代优化
   ↓
6. 文档化模板
```

#### 7.2 常见陷阱

**陷阱1: 提示词过于简单**
```
❌ "分析数据"
✅ "分析以下销售数据，计算关键指标，识别趋势，输出结构化报告"
```

**陷阱2: 缺少上下文**
```
❌ "优化代码"
✅ "作为资深Python工程师，优化以下代码的性能和可读性：[代码]"
```

**陷阱3: 格式要求不明确**
```
❌ "列出问题"
✅ "按以下格式列出问题：
- 问题1: [描述]
- 问题2: [描述]"
```

**陷阱4: 忽略边界情况**
```
❌ "如果出错就重试"
✅ "如果工具调用失败：
1. 检查参数是否正确
2. 重试最多3次
3. 如果仍失败，返回错误信息并建议替代方案"
```

### 8. 提示词与Agent架构的整合

**在Agent循环中的应用:**
```
1. 感知阶段: 使用提示词理解用户输入
2. 规划阶段: 使用提示词分解任务
3. 执行阶段: 使用提示词调用工具
4. 反思阶段: 使用提示词评估结果
5. 记忆阶段: 使用提示词总结和存储
```

**提示词层次结构:**
```
系统级提示词 (System Prompt)
    ↓
任务级提示词 (Task Prompt)
    ↓
工具级提示词 (Tool Prompt)
    ↓
输出格式化提示词 (Format Prompt)
```

**面试重点**
- ✅ 理解提示词工程的核心价值
- ✅ 掌握基础提示词模式（Zero-shot、Few-shot、CoT、Role-based）

## 四、工具调用（高频）⭐⭐⭐⭐⭐

### 1. Function Calling 原理

**什么是Function Calling？**
- LLM 根据用户意图，决定调用哪个工具
- 生成工具调用的参数
- 获取结果后继续推理

**流程:**
```
用户输入
    ↓
LLM理解意图
    ↓
选择合适的工具
    ↓
生成工具参数
    ↓
执行工具调用
    ↓
获取结果
    ↓
LLM整合结果
    ↓
返回最终答案
```

### 2. 工具定义

**Schema定义:**
```json
{
  "name": "get_weather",
  "description": "获取指定城市的天气信息",
  "parameters": {
    "type": "object",
    "properties": {
      "city": {
        "type": "string",
        "description": "城市名称，如'北京'"
      },
      "date": {
        "type": "string",
        "description": "日期，格式YYYY-MM-DD"
      }
    },
    "required": ["city"]
  }
}
```

### 3. 工具选择策略

- **单工具**: 简单明确的任务
- **多工具串行**: 需要多步骤，有依赖关系
- **多工具并行**: 独立的多个子任务

### 4. 常见工具类型

- 🔍 搜索工具（Google、Bing、Wikipedia）
- 🧮 计算工具（Calculator、Python REPL）
- 📊 数据库查询（SQL）
- 🌐 API调用（天气、地图、股票）
- 💻 代码执行（Python、JavaScript）

## 五、记忆系统 ⭐⭐⭐⭐

### 1. 短期记忆（Working Memory）

**特点:**
- 保存当前对话历史
- 上下文窗口限制
- 实现：滑动窗口、摘要压缩

**示例:**
```
对话1: "我叫张三"
对话2: "我喜欢AI"
对话3: "我的名字是什么？"

Agent回答: "您的名字是张三"
→ 从短期记忆中检索
```

### 2. 长期记忆（Long-term Memory）

**特点:**
- 持久化存储
- 知识库、向量数据库
- 实现：RAG（检索增强生成）

**类型:**
- **语义记忆**: 事实知识（如"北京是中国首都"）
- **情节记忆**: 历史对话、用户偏好
- **程序记忆**: 学到的技能、工具使用经验

### 3. 向量记忆

**实现:**
```
1. 将记忆转换为向量
2. 存储到向量数据库
3. 根据相似度检索
4. 整合到上下文
```

## 六、Agent架构 ⭐⭐⭐⭐

### 1. 单Agent架构

**基础模式:**
```
Perception (感知) → Planning (规划) → Execution (执行)
```

**实现方式:**
- **Reflexion**: 自我反思，从错误中学习
- **Self-Ask**: 自问自答，逐步分解问题
- **Toolformer**: 自主学习何时使用工具

### 2. 多Agent架构

**协作模式:**
- **主从模式**: 一个管理者Agent + 多个执行Agent
- **平等协作**: 多个Agent讨论协商
- **专家系统**: 不同领域的专家Agent

**通信机制:**
- 共享内存
- 消息传递
- 黑板系统

### 3. Agent循环

```python
while not done:
    # 1. 感知环境
    observation = environment.get_state()
    
    # 2. 推理决策
    thought = agent.think(observation)
    action = agent.decide(thought)
    
    # 3. 执行动作
    result = agent.execute(action)
    
    # 4. 更新记忆
    agent.memory.update(observation, action, result)
    
    # 5. 检查是否完成
    done = agent.is_task_complete()
```
