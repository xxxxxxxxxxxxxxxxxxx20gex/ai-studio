## 一、微调方法整体对比

从「可训练参数量 / 显存占用 / 训练难度 / 适用场景」四个维度对比几种常见方法：

```text
| 方法             | 可训练参数量 | 显存占用 | 训练难度 | 典型适用场景           |
|------------------|--------------|----------|----------|------------------------|
| 全量微调         | 100%         | 很高     | 中等     | 小模型、资源充足      |
| LoRA             | < 1%         | 低       | 低       | 通用推荐首选          |
| Adapter          | 2% ~ 5%      | 低       | 低       | 需要更强表达能力      |
| Prompt Tuning    | < 0.1%       | 极低     | 中等     | 超大模型 (10B+)       |
| Prefix Tuning    | < 1%         | 低       | 中等     | 生成任务              |
```

## 二、LoRA（Low-Rank Adaptation）

> 对应代码：`code/lora.py`

### 2.1 核心思想

- 冻结预训练权重 \(W\)，不直接更新它；
- 为某些线性层（如 Q/K/V 投影层）添加一个低秩矩阵 \(\Delta W = BA\)；
- 仅训练 \(A, B\)，在推理时可以把 \(\Delta W\) 合并回原权重，几乎无额外开销。

数学形式：

```text
原始：h = W · x
LoRA：h = W · x + (B · A) · x = (W + ΔW) · x

其中：
- W ∈ R^(d×k)：预训练权重（冻结）
- A ∈ R^(r×k)：下投影矩阵（训练）
- B ∈ R^(d×r)：上投影矩阵（训练）
- r：秩，一般远小于 d, k（例如 r=4/8/16）
```

### 2.2 参数量优势示例

```text
假设 d = k = 1024, r = 8

原始权重参数量：d × k = 1,048,576
LoRA 新增参数量：r × (d + k) = 8 × (1024 + 1024) = 16,384

参数减少比例 ≈ 98.4%
```

### 2.3 典型使用位置

- 自注意力层中的 Q、K、V 投影；
- 输出投影层；
- 有时也会加在 FFN 的部分线性层上。

### 2.4 优缺点小结

- **优点：**
  - 参数极少，易于在消费级显卡上训练；
  - 可以为不同下游任务保存多组 \(A,B\)，方便「多任务切换」；
  - 推理时支持把 LoRA 权重「合并」，不引入额外推理开销。
- **缺点：**
  - 低秩假设不一定完全成立，表达能力有上限；
  - 需要对秩 r 做一些调参。

## 三、Adapter（适配器）

> 对应代码：`code/adapter.py`

### 3.1 架构

在 Transformer 的某些位置插入一个小的「瓶颈 MLP」模块：

```text
输入 (d 维)
  ↓
下投影 (d → m)     # m ≪ d，例如 64
  ↓
非线性激活 (ReLU/GELU)
  ↓
上投影 (m → d)
  ↓
残差连接（加回输入）
  ↓
输出 (d 维)
```

### 3.2 特点

- 只训练 Adapter 内部的参数，原始 Transformer 权重完全冻结；
- 可以在「自注意力之后」「FFN 之后」等多个位置插入；
- 每个 Adapter 参数量大约是 \(2dm\)，整体仍远小于全量微调。

### 3.3 优缺点小结

- **优点：**
  - 初始可以设为近似恒等映射，不破坏原始模型；
  - 表达能力普遍强于 LoRA（参数稍多，但更灵活）。
- **缺点：**
  - 推理时无法完全合并到原权重中，仍有少量额外计算；
  - 总参数量比 LoRA 稍大。

## 四、Prompt Tuning / Prefix Tuning（提示学习）

> 对应代码：`code/prompt_tuning.py`

### 4.1 Prompt Tuning（软提示）

核心做法：

```text
传统输入：
  [CLS] I love this movie [SEP]

Prompt Tuning：
  [P1] [P2] ... [Pk] I love this movie [SEP]
   ↑    ↑        ↑
  可学习的“软提示”向量
```

只训练这部分连续的 embedding（Prompt 向量），主干模型完全冻结。

**参数量示例：**

```text
假设提示长度 k = 20，隐藏维度 d_model = 768
可训练参数量 = 20 × 768 = 15,360
相比于一个 110M 的 BERT，仅占约 0.014%
```

### 4.2 Prefix Tuning

- 在 Transformer 每一层的 K/V 前面 prepend 一段可学习向量；
- 类似为每一层前面加一段「上下文前缀」；
- 参数量略多于简单的 Prompt Tuning，但效果更好，尤其在生成任务中。

### 4.3 适用场景与特点

- 非常适合超大模型（10B+），因为训练参数极少；
- 对小模型时，效果有时不如 LoRA / Adapter；
- 常与指令微调、RLHF 等方案组合使用。

## 五、实践选择建议（如何在项目中选方案）

> 下面是一个实战导向的「简单决策表」，帮助快速选型。

### 5.1 场景 1：通用下游任务，显存有限

- **推荐：LoRA**
  - rank 取 8/16；
  - 优先加在注意力层的 Q/K/V 上；
  - 可以配合 PEFT 等库快速上手。

### 5.2 场景 2：任务复杂，需要更强表达能力

- **候选：Adapter +（或）LoRA 组合**
  - 在关键信号流（如 FFN、输出层）附近插 Adapter；
  - 对部分注意力层加 LoRA 微调。

### 5.3 场景 3：超大模型（>10B）上的个性化任务

- **推荐：Prompt Tuning / Prefix Tuning**
  - 参数极小，显存占用、存储成本极低；
  - 可以为大量用户/任务分别维护一组提示向量。

### 5.4 场景 4：多任务、可切换场景

- LoRA 与 Prompt Tuning 都适合「为每个任务一套参数」，在运行时按需加载；
- 可以把基础模型当作底座，通过加载不同 LoRA / Prompt 权重快速切换任务。
