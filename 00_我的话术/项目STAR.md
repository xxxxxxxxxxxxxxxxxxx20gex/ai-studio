# 项目 STAR 讲法

> 每个项目按：背景痛点 → 我做了什么 → 结果数字 → 我学到了什么。先讲业务价值，再讲技术。

---

## 项目一：WujieAI 数学科研 Agent 平台（当前主项目）

- **S 背景**：高难度数学研究链路长、工具多，靠人手工串文献检索、计算、证明效率低；模型直接做精确计算幻觉大。
- **T 任务**：我负责 Agent 编排、工具生态和运行时架构，推动平台从框架式多 Agent 演进为通用科研智能体基础设施。
- **A 行动**：
  1. 第一代 Agno：DeepSeek V3.1 + Tool Calling + LightRAG + Mem0，统一会话、知识、记忆；
  2. 第二代 OpenClaw：把检索/PDF/计算能力重构成可复用 Skill，加多角色群体研讨和钉钉/飞书人在回路；
  3. 第三代 Codex Harness：迁到通用执行底座，工具封装成 MCP Server/Plugin，打通 GPT-5.6 + Codex + Lean4 形式化证明链路。
- **R 结果**：服务公司及浙大、南大、中山、西湖等高校；为团队完成一项百年数学问题证明提供技术支撑。
- **⚠️ 贡献边界**：百年数学问题是**团队成果**，我负责的是背后的平台和自动化链路，不要说"我证明了"。

## 项目二：多模型 AI 网关

- **S 背景**：上层科研 Agent 要对接多家模型，缺统一入口，安全和计费没人管。
- **T 任务**：基于 Go 建统一模型控制面。
- **A 行动**：兼容 OpenAI/Claude/Gemini/DeepSeek/Qwen/Kimi 等协议；做多渠道路由、渠道亲和、失败重试；做 API Key 鉴权、限流、预扣/补扣计费；用 Nginx 做边缘防护。
- **R 结果**：近 15 天处理 31.2 万+ 边缘请求、22.3 万+ 模型请求，拦截恶意扫描 31249 次（69 个 IP），触发 429 限流 5886 次。
- **⚠️ 数字口径**：被追问时要说清是"近 15 天"统计窗口、是生产环境数据。

## 项目三：Nestflo 房产智能客服 Agent

- **S 背景**：房产咨询大量重复问题，人工客服成本高、响应慢。
- **T 任务**：从 0 到 1 搭覆盖租前咨询、房源推荐、预约、租后支持的多 Agent 平台。
- **A 行动**：多 Agent 路由 + 智能诊断 + 自助服务；结合语音识别和情感分析处理客服录音，做客户价值评估和服务质检。
- **R 结果**：服务 1k+ 用户，简单问题人工处理量减少约 80%。
- **⚠️ 数字口径**：80% 是"简单问题"口径，别说成"整体客服降本 80%"。
